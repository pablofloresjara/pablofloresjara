Bienvenido a esta sesión magistral. En este módulo exploraremos los cimientos de la Programación Orientada a Objetos (POO), el paradigma dominante en la ingeniería de software moderna, esencial para modelar sistemas telemáticos y aplicaciones robustas.

Introducción a la Programación Orientada a Objetos

Orígenes

El paradigma no surgió de la noche a la mañana. Sus raíces se remontan a finales de los años 60 con Simula 67, diseñado por Dahl y Nygaard en Noruega para crear simulaciones de sistemas. Posteriormente, en los 70, Alan Kay y su equipo en Xerox PARC desarrollaron Smalltalk, consolidando los conceptos de "objeto" y "paso de mensajes".

El auge industrial llegó en los 80s y 90s con C++ y, definitivamente, con Java, transformando la POO en el estándar de la industria.

Objetivos Principales

  • Mantenibilidad: Facilitar la modificación del software sin afectar el sistema completo (aislamiento de fallos).
  • Reutilización: Escribir código una vez y usarlo en múltiples contextos a través de herencia y composición.
  • Abstracción: Modelar entidades complejas del mundo real enfocándose en sus características esenciales y ocultando detalles técnicos.

En resumen: La POO deja de ver a los programas como una simple secuencia de instrucciones y los concibe como una colección de objetos que interactúan entre sí.

Clases

Una Clase es el pilar fundamental de la POO. Es una estructura o modelo lógico que define el estado y el comportamiento que tendrán todos los objetos de ese tipo. Es, conceptualmente, un tipo de dato definido por el usuario.

La Analogía del Plano Arquitectónico

Piensa en una clase como el plano de una casa trazado por un arquitecto. El plano en sí no es una casa (no puedes vivir en él, ni tiene puertas físicas), pero define exactamente cómo será la casa: cuántas habitaciones tendrá, dónde van las ventanas y de qué color serán las paredes.

A partir de ese único plano (la clase), un constructor puede edificar múltiples casas reales (los objetos).

class Vehiculo {
  // Molde estructural
  String marca;
  int velocidadMax;
}

Objetos

Si la clase es el molde, el Objeto es la entidad física o lógica creada a partir de ese molde. Formalmente, a un objeto se le conoce como una instancia de una clase. Durante la ejecución del programa, los objetos ocupan espacio en la memoria y realizan el trabajo real del software.

Todo Objeto posee tres componentes fundamentales (Grady Booch):

Estado

Es la suma de todos los valores de las variables internas del objeto en un momento determinado. ¿Está encendido o apagado? ¿Cuál es su nombre?

Comportamiento

Es cómo actúa y reacciona el objeto. Son las acciones que puede realizar y cómo su estado interno puede cambiar mediante dichas acciones.

Identidad

Es la propiedad que distingue a un objeto de todos los demás. Incluso si dos objetos tienen exactamente el mismo estado, siguen siendo dos entidades distintas en memoria.

Atributos y Métodos

Definición

Atributos (Datos)

También conocidos como variables de instancia o campos. Representan el Estado del objeto. Son los datos que caracterizan y definen de manera individual a un objeto determinado.

Métodos (Acciones)

También conocidos como funciones miembro u operaciones. Representan el Comportamiento del objeto. Son los bloques de código que se ejecutan cuando un objeto recibe un "mensaje".

Características

Los atributos y métodos poseen características técnicas específicas que definen cómo el compilador y otros objetos interactúan con ellos:

Característica En Atributos En Métodos
Tipado Tienen un tipo de dato estricto (int, String, etc.) o tipo por referencia. Tienen un tipo de retorno (incluyendo void si no retornan nada).
Visibilidad Suelen ser private para proteger el estado (Ocultación de datos). Suelen ser public para definir la interfaz de interacción del objeto.
Firma Se identifican por su nombre dentro de la clase. Tienen una "Firma": su nombre + lista de parámetros (permite Sobrecarga).

Propiedades (Encapsulamiento)

En ingeniería de software orientada a objetos, rara vez se expone un atributo de forma directa (haciéndolo public). En su lugar, se utilizan Propiedades. Una propiedad es una combinación conceptual de un atributo encapsulado y métodos de acceso que lo controlan.

  • Métodos Getters (Obtener): Permiten leer el valor de un atributo desde el exterior sin modificarlo.
  • Métodos Setters (Establecer): Permiten modificar el valor de un atributo, pero pasando por filtros de validación, asegurando la integridad del objeto.
Integridad: Si tuviéramos un atributo edad público, alguien podría asignarle -5. Al usar una Propiedad (un Setter), podemos incluir lógica que lance un error si la edad provista es menor que cero.

Ejemplos Prácticos en Java

Ejemplo 1: Cuenta Bancaria (Conceptos Básicos)

Muestra la definición clásica de Atributos, Constructor, Métodos y el encapsulamiento de un saldo que no puede ser negativo.

CuentaBancaria.java 
public class CuentaBancaria {
    // Atributos encapsulados (privados)
    private String titular;
    private double saldo; 

    // Constructor
    public CuentaBancaria(String titular) {
        this.titular = titular;
        this.saldo = 0.0; // Estado inicial
    }

    // Getter: Solo lectura
    public double getSaldo() {
        return this.saldo;
    }

    // Métodos de comportamiento
    public void depositar(double cantidad) {
        if (cantidad > 0) {
            this.saldo += cantidad;
            System.out.println("Depósito exitoso.");
        }
    }

    public boolean retirar(double cantidad) {
        // Lógica de protección: No se puede retirar más de lo que hay
        if (cantidad > 0 && this.saldo >= cantidad) {
            this.saldo -= cantidad;
            return true;
        }
        return false; 
    }
}

Ejemplo 2: Vehículos (Instancias Múltiples)

Demuestra cómo a partir de una sola clase podemos crear múltiples objetos, cada uno con su propia "Identidad" y "Estado" en memoria.

Vehiculo.java 
public class Vehiculo {
    private String marca;
    private int velocidadActual;

    public Vehiculo(String marca) {
        this.marca = marca;
        this.velocidadActual = 0;
    }

    public void acelerar(int incremento) {
        this.velocidadActual += incremento;
    }

    public String getEstado() {
        return "El vehículo " + this.marca + " va a " + this.velocidadActual + " km/h";
    }
}

// --- Clase Ejecutable ---
class MainVehiculos {
    public static void main(String[] args) {
        // Creando dos instancias DISTINTAS de la misma clase
        Vehiculo coche1 = new Vehiculo("Toyota");
        Vehiculo coche2 = new Vehiculo("Ford");

        // Modificando estados de manera independiente
        coche1.acelerar(50);
        coche2.acelerar(80);

        System.out.println(coche1.getEstado()); // Imprime: ...Toyota va a 50 km/h
        System.out.println(coche2.getEstado()); // Imprime: ...Ford va a 80 km/h
    }
}

Ejemplo 3: Estudiante (Setters y Validaciones)

Enfocado en demostrar por qué usamos los métodos "Set" en lugar de hacer la variable pública. Observa cómo el sistema rechaza una calificación imposible.

Estudiante.java 
public class Estudiante {
    private String nombre;
    private double notaFinal;

    public Estudiante(String nombre) {
        this.nombre = nombre;
        this.notaFinal = 0.0;
    }

    // Setter con validación de datos (Filtro)
    public void setNotaFinal(double nota) {
        if (nota >= 0.0 && nota <= 10.0) {
            this.notaFinal = nota;
            System.out.println("Nota actualizada con éxito.");
        } else {
            System.err.println("Error: La nota debe estar entre 0.0 y 10.0");
        }
    }
}

Ejemplo 4: Libro (Comportamientos como Estados Lógicos)

Muestra un objeto que cambia de un estado lógico a otro mediante métodos, representando un libro en una biblioteca que puede ser prestado y devuelto.

Libro.java 
public class Libro {
    private String titulo;
    private boolean estaPrestado; // Atributo booleano de estado

    public Libro(String titulo) {
        this.titulo = titulo;
        this.estaPrestado = false; // Por defecto está en la biblioteca
    }

    // Método que muta el estado a 'Prestado'
    public void prestar() {
        if (!this.estaPrestado) {
            this.estaPrestado = true;
            System.out.println("El libro '" + this.titulo + "' ha sido prestado.");
        } else {
            System.out.println("Lo sentimos, el libro ya está prestado.");
        }
    }

    // Método que muta el estado a 'Disponible'
    public void devolver() {
        if (this.estaPrestado) {
            this.estaPrestado = false;
            System.out.println("Gracias por devolver '" + this.titulo + "'.");
        } else {
            System.out.println("Este libro ya estaba en la biblioteca.");
        }
    }
}
