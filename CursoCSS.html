CSS Moderno - Ingeniería de Sistemas

Temario del Curso

Un curso de CSS diseñado para estudiantes de Ingeniería de Sistemas, enfocado en la arquitectura, el rendimiento y las buenas prácticas.

Módulo 1: Fundamentos y Conceptos Centrales

Este módulo establece el "modelo mental" de CSS. Para un ingeniero, entender por qué algo funciona es tan importante como cómo funciona.

1.1 ¿Qué es CSS?

Concepto (Teoría): CSS (Cascading Style Sheets - Hojas de Estilo en Cascada) es el lenguaje declarativo que controla la presentación visual de un documento web. Su principio fundamental es la Separación de Responsabilidades (Separation of Concerns - SoC), un pilar de la ingeniería de software.

  • HTML: Define la estructura y el significado (semántica) del contenido.
  • CSS: Define la presentación (colores, fuentes, layout).
  • JavaScript: Define el comportamiento (interactividad, lógica).

Autores (Historia): El concepto fue propuesto por Håkon Wium Lie en 1994. Bert Bos fue co-creador y juntos publicaron la primera especificación (CSS 1) en 1996 bajo el auspicio del W3C (World Wide Web Consortium), que sigue siendo el organismo de estandarización.

Sintaxis Básica:

  • Selector: El patrón que "apunta" al elemento HTML.
  • Declaración: El par propiedad: valor.
  • Regla: El conjunto de selector y bloque de declaraciones.

Ejemplo Práctico:

<!-- index.html -->
<p class="error-message">Error: No se pudo conectar al servidor.</p>
/* style.css */
/* Esto es una regla CSS */
.error-message { /* Esto es el Selector (apunta a la clase 'error-message') */
  color: #f472b6;         /* rosa */
  font-weight: bold;  
  border: 1px solid #f472b6;
  background: rgba(244, 114, 182, 0.1);
  padding: 10px;
  border-radius: 5px;
}

1.2 Formas de Incluir CSS

Concepto (Teoría): Existen tres métodos, pero solo uno es escalable. La elección impacta directamente el rendimiento (caching) y la mantenibilidad.

  1. CSS Externo (Recomendado): Un archivo .css separado, enlazado en el <head>.
    • Ventaja: El navegador lo guarda en caché. Si el usuario visita 10 páginas que usan el mismo .css, solo lo descarga una vez. Máxima mantenibilidad.
  2. CSS Interno: Usando la etiqueta <style> dentro del <head>.
    • Ventaja: Útil para estilos que solo aplican a una página específica o para prototipado rápido.
  3. CSS En Línea: Usando el atributo style directamente en la etiqueta HTML.
    • Desventaja: Rompe la Separación de Responsabilidades. Tiene la máxima especificidad (ver 1.4), lo que lo hace muy difícil de sobrescribir. Considerado una mala práctica en el desarrollo de aplicaciones.

Ejemplo Práctico:

<!DOCTYPE html>
<html>
<head>
  <!-- 1. CSS Externo (Mejor práctica) -->
  <link rel="stylesheet" href="estilos.css">

  <!-- 2. CSS Interno -->
  <style>
    body {
      background-color: #f0f0f0; /* Estilo solo para esta página */
    }
  </style>
</head>
<body>
  <!-- 3. CSS En Línea (Mala práctica) -->
  <h1 style="color: blue; font-size: 30px;">
    Este título rompe la SoC
  </h1>
  <p>Este párrafo usará los estilos de 'estilos.css' y el fondo del CSS interno.</p>
</body>
</html>

1.3 Selectores: El Arte de Apuntar

Concepto (Teoría): Los selectores son el "lenguaje de consulta" de CSS. Su eficiencia impacta el rendimiento del renderizado. El navegador evalúa los selectores de derecha a izquierda. Por eso, un selector body .menu-item es menos eficiente que .menu-item.

Ejemplos Prácticos (Tipos):

<div id="main-content">
  <p class="highlight">Texto destacado.</p>
  <p>Texto normal.</p>
  <a href="https://google.com" target="_blank">Google</a>
  <nav>
    <ul>
      <li><a href="/">Inicio</a></li>
    </ul>
  </nav>
</div>
/* 1. Selector de Tipo (Elemento) */
p { font-family: Arial, sans-serif; }

/* 2. Selector de Clase (El más usado y recomendado) */
.highlight { background-color: rgba(163, 230, 53, 0.2); } /* lime-400 con opacidad */

/* 3. Selector de ID (Muy específico, usar con moderación) */
#main-content { max-width: 800px; }

/* 4. Selector de Atributo */
a[target="_blank"] { /* Solo enlaces que abren en pestaña nueva */
  /* background-image: url('external-link.svg'); */
  /* Usamos un pseudo-elemento para un look más moderno */
  position: relative;
  padding-right: 1.2em;
}

a[target="_blank"]::after {
    content: '↗'; /* O un SVG */
    position: absolute;
    right: 0;
    top: 0;
    font-size: 0.8em;
    color: #a3e635; /* lime-400 */
}

/* 5. Combinador Descendiente (espacio) */
#main-content p { /* Cualquier 'p' dentro de '#main-content' */
  line-height: 1.6;
}

/* 6. Combinador de Hijo Directo (>) */
nav > ul { /* Solo 'ul' que es hijo directo de 'nav' */
  list-style-type: none;
}

/* 7. Combinador Adyacente Siguiente (+) */
.highlight + p { /* El 'p' que viene INMEDIATAMENTE después de '.highlight' */
  margin-top: 20px;
}

1.4 La Cascada, Especificidad y Herencia

Esta es la teoría de algoritmos fundamental de CSS.

Concepto (La Cascada): Es el algoritmo que decide qué regla CSS aplicar cuando hay un conflicto. El orden de prioridad es:

  1. Importancia: Las declaraciones con !important ganan (casi) siempre. (Usar !important es una mala práctica, es "ganar por la fuerza" y genera deudas técnicas).
  2. Origen: De dónde viene el CSS. El orden es: Autor (nuestro .css) > Usuario (configuración del navegador) > User-Agent (estilos por defecto del navegador).
  3. Especificidad: Qué selector es "más específico" (ver abajo).
  4. Orden de Fuente: Si todo lo demás es igual, la última regla declarada en el código gana.

Concepto (Especificidad): Es el sistema de "puntos" para calcular el peso de un selector. Se puede pensar como una tupla de 4 números: (Inline, ID, Clase, Elemento).

  • Estilos en Línea (Inline): (1, 0, 0, 0) - El más alto.
  • IDs: (0, 1, 0, 0)
  • Clases, Pseudo-clases, Atributos: (0, 0, 1, 0)
  • Elementos, Pseudo-elementos: (0, 0, 0, 1)

Ejemplo Práctico (Especificidad):

<div id="app">
  <p class="text-primary">Hola Mundo</p>
</div>
/* Especificidad: (0,0,0,1) */
p {
  color: red;
}

/* Especificidad: (0,0,1,1) -> Gana a la anterior */
p.text-primary {
  color: blue;
}

/* Especificidad: (0,1,0,1) -> Gana a la anterior */
#app p {
  color: green;
}

/* Especificidad: (0,1,1,1) -> Gana a la anterior */
#app p.text-primary {
  color: purple; /* <-- Este es el color que se aplicará */
}

/* ¡El orden no importa si la especificidad es mayor! */
p {
  color: orange; /* Sigue perdiendo, aunque esté al final */
}

Concepto (Herencia): Propiedades que fluyen "hacia abajo" en el árbol DOM.

  • Heredan: Propiedades de texto (color, font-family, font-size, line-height, text-align).
  • No Heredan: Propiedades del modelo de caja (padding, margin, border, width, height) y fondos (background).

Ejemplo Práctico (Herencia):

<div class="container">
  Soy el padre.
  <p>Soy el hijo.</p>
</div>
.container {
  color: #a3e635;         /* lime-400 (Heredable) */
  border: 1px solid #f472b6; /* pink-400 (No heredable) */
}
/*
Resultado:
- El 'div.container' tendrá borde rosa y texto verde.
- El 'p' (hijo) tendrá texto verde (heredado), pero NO tendrá borde.
*/

1.5 El Modelo de Caja (The Box Model)

Concepto (Teoría): Es el modelo de renderizado fundamental del navegador. Cada elemento HTML es una caja rectangular. Esta caja se compone de cuatro capas, de adentro hacia afuera:

  1. Content: El contenido (texto, imagen).
  2. Padding: Relleno interno (espacio entre contenido y borde).
  3. Border: El borde.
  4. Margin: El margen externo (espacio entre esta caja y las cajas vecinas).

Concepto (box-sizing): Esta propiedad define cómo se calcula el width y height de la caja.

  • content-box (default antiguo): width = solo el contenido. El padding y border se suman al ancho total.
  • border-box (estándar moderno): width = contenido + padding + borde. Es el modelo más intuitivo y fácil de gestionar. Paul Irish fue uno de los grandes promotores de su adopción generalizada.

Ejemplo Práctico (border-box vs content-box):

<div class="box content-box">Content Box</div>
<div class="box border-box">Border Box</div>
/* Un "reset" común que facilita la vida */
*, *::before, *::after {
  box-sizing: border-box;
}

.box {
  width: 200px;
  padding: 20px;
  border: 5px solid #a3e635; /* lime-400 */
  margin: 10px;
  background: #1f2937; /* bg-gray-800 */
  color: white;
}

.content-box {
  /* Este 'box-sizing' es el default, lo forzamos para el ejemplo */
  box-sizing: content-box;
  /*
  Ancho Total Calculado:
  width (200px) + padding (20px*2) + border (5px*2) = 250px
  */
}

.border-box {
  /*
  Ancho Total Calculado:
  El width (200px) YA INCLUYE el padding y el borde.
  El área de contenido se reduce automáticamente a 150px.
  El ancho total sigue siendo 200px.
  */
}

Módulo 2: Propiedades Esenciales y Tipografía

Construir los "átomos" de la interfaz.

2.1 Unidades y Valores

Concepto (Teoría): Las unidades definen cómo se mide un valor. Se dividen en Absolutas (fijas) y Relativas (flexibles).

  • Absolutas: px (Píxeles). Bueno para elementos que nunca deben cambiar (ej. un border-width de 1px).
  • Relativas (al Viewport): vw (1% del ancho del viewport), vh (1% del alto del viewport).
  • Relativas (a la Tipografía):
    • %: Relativo al mismo valor en el elemento padre.
    • em: Relativo al font-size del elemento padre. Puede causar anidamiento complejo (efecto "compuesto").
    • rem (Root EM): Relativo al font-size del elemento raíz (<html>). Es la unidad preferida para la escalabilidad y accesibilidad, ya que todo el layout y tipografía pueden escalar uniformemente si el usuario cambia el tamaño de fuente base en su navegador.

Ejemplo Práctico (rem vs em):

<html> <!-- font-size: 16px (default) -->
<body>
  <div class="padre-em" style="font-size: 1.2em;"> <!-- 16px * 1.2 = 19.2px -->
    <p style="font-size: 1.2em;"> <!-- 19.2px * 1.2 = 23.04px (complicado) -->
      Texto con 'em'
    </p>
  </div>

  <div class="padre-rem">
    <p style="font-size: 1.2rem;"> <!-- 16px * 1.2 = 19.2px (predecible) -->
      Texto con 'rem'
    </p>
  </div>
</body>
</html>
/*
Usar 'rem' para márgenes, paddings y tipografía permite que toda
la UI escale si el usuario necesita texto más grande.
*/
.componente {
  padding: 1rem; /* 16px */
  margin-bottom: 0.5rem; /* 8px */
  font-size: 1.1rem; /* 17.6px */
}

2.2 Colores y Fondos

Concepto (Teoría): Definición de color.

  • Formatos:
    • HEX: #FF0000 (RRGGBB).
    • RGB: rgb(255, 0, 0).
    • RGBA: rgba(255, 0, 0, 0.5) (El canal "A" es Alpha o transparencia, de 0 a 1).
    • HSL: hsl(0, 100%, 50%) (Hue, Saturation, Lightness - Tono, Saturación, Luminosidad). Más intuitivo para ajustes humanos. HSLA añade transparencia.
  • Propiedades de background: Permiten un control granular sobre el fondo.

Ejemplo Práctico (Fondo complejo):

<div class="hero-section">
  <h1>Bienvenido</h1>
</div>
.hero-section {
  /* Cargar una imagen (placeholder de un servicio externo) */
  background-image: url('https://placehold.co/1200x400/333/eee?text=Hero+Image');

  /* Asegurar que la imagen cubra todo el contenedor */
  background-size: cover;

  /* Centrar la imagen */
  background-position: center center;

  /* Evitar que la imagen se repita */
  background-repeat: no-repeat;

  /* (Atajo para todo lo anterior)
  background: url('...') center/cover no-repeat;
  */

  /* Añadir un color semi-transparente SOBRE la imagen para legibilidad */
  /* Esta vez un gradiente de moda */
  background-image:
    linear-gradient(to right, rgba(163, 230, 53, 0.4), rgba(236, 72, 153, 0.4)),
    url('https://placehold.co/1200x400/333/eee?text=Hero+Image');

  height: 400px;
  color: white; /* Texto blanco para contraste */
  
  /* Centrar el h1 (usando flexbox) */
  display: flex;
  justify-content: center;
  align-items: center;
  border-radius: 10px;
}

2.3 Tipografía Web

Concepto (Teoría): El control sobre el texto es clave para la Usabilidad y Accesibilidad (UX/UI).

  • font-family: Lista de fuentes (stack). Termina con una genérica (ej. sans-serif o serif).
  • @font-face: La regla CSS que permite cargar archivos de fuentes personalizadas (ej. .woff2, .ttf) alojados en nuestro servidor.
  • line-height: (Altura de línea). Crucial para la legibilidad. Se recomienda usar valores sin unidad (ej. line-height: 1.6;), que son un múltiplo del font-size del propio elemento.

Ejemplo Práctico (Google Fonts y legibilidad):

<!-- 1. Cargar Google Fonts en el <head> -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&family=Lora&display=swap" rel="stylesheet">

<article>
  <h2>Título del Artículo</h2>
  <p>Este es un párrafo de texto...</p>
</article>
body {
  /* Fuente 'sans-serif' para legibilidad general */
  font-family: 'Roboto', Arial, sans-serif;
  line-height: 1.6; /* 160% del font-size */
  font-size: 16px;
}

h2 {
  /* Fuente 'serif' para títulos (contraste) */
  font-family: 'Lora', Georgia, serif;
  font-weight: 700; /* Negrita */
  line-height: 1.2; /* Títulos tienen menos altura de línea */
  text-transform: uppercase; /* Mayúsculas */
}

p {
  text-align: justify; /* Justificado (cuidado con ríos de texto) */
  letter-spacing: 0.5px; /* Espaciado entre letras */
}

2.4 El Flujo del Documento (Propiedad display)

Concepto (Teoría): Es el concepto más básico de layout. Todo elemento tiene un valor display por defecto que define cómo interactúa con sus vecinos.

  • display: block:
    • Ocupa todo el ancho disponible.
    • Crea un salto de línea antes y después.
    • Respeta width, height, margin y padding.
    • (Ej: <div>, <p>, <h1>, <section>)
  • display: inline:
    • Ocupa solo el ancho de su contenido.
    • Fluye con el texto, no crea saltos de línea.
    • Ignora width, height, y margin-top/bottom.
    • (Ej: <span>, <a>, <strong>)
  • display: inline-block:
    • El "híbrido". Fluye con el texto (como inline), pero respeta width, height, margin y padding (como block).
  • display: none:
    • Elimina el elemento del DOM. No ocupa espacio y no es visible. (Diferente de visibility: hidden, que lo oculta pero reserva su espacio).

Ejemplo Práctico:

<a href="#" class="btn-block">Botón Block</a>
<a href="#" class="btn-block">Botón Block</a>

<span class="etiqueta-inline">Etiqueta 1</span>
<span class="etiqueta-inline">Etiqueta 2</span>

<a href="#" class="btn-inline-block">Botón IB</a>
<a href="#" class="btn-inline-block">Botón IB</a>
.btn-block {
  display: block;
  background: #a3e635; /* bg-lime-400 */
  color: #1f2937; /* bg-gray-800 */
  font-weight: 600;
  margin: 10px 0; /* Se apilan verticalmente */
  padding: 10px;
  text-align: center;
  border-radius: 5px;
}

.etiqueta-inline {
  display: inline;
  background: #ec4899; /* bg-pink-500 */
  color: white;
  padding: 0.2em 0.4em;
  border-radius: 3px;
}

.btn-inline-block {
  display: inline-block;
  background: #6366f1; /* bg-indigo-500 */
  color: white;
  margin: 10px; /* Respeta márgenes en todas direcciones */
  padding: 10px; /* Respeta padding */
  width: 150px; /* Respeta width */
  text-align: center;
  border-radius: 5px;
}

Módulo 3: Layouts Modernos (Flexbox y Grid)

El abandono de técnicas antiguas (como float) para maquetar.

3.1 Position: El Layout Clásico

Concepto (Teoría): La propiedad position permite sacar elementos del "flujo normal" del documento.

  • static: El valor por defecto. El elemento sigue el flujo normal.
  • relative: El elemento sigue en el flujo, pero ahora podemos "moverlo" con top, right, bottom, left relativo a su posición original. Lo más importante: crea un contexto de posicionamiento para sus hijos absolute.
  • absolute: El elemento se saca completamente del flujo. Se posiciona (con top, left, etc.) relativo a su ancestro posicionado más cercano (cualquier ancestro que no sea position: static). Si no encuentra ninguno, se posiciona relativo al <body>.
  • fixed: Se saca del flujo. Se posiciona relativo al viewport (la ventana del navegador). No se mueve al hacer scroll.
  • sticky: Un híbrido. Se comporta como relative hasta que el scroll llega a un punto (definido por top, bottom, etc.), y entonces se "pega" y actúa como fixed.

Ejemplo Práctico (Modal y Header Fijo):

<header class="header-sticky">Header Fijo</header>
<div class="modal-backdrop">
  <div class="modal-content">
    <!-- 'position: relative' en el padre... -->
    <button class="modal-close-btn">X</button> <!-- ...para posicionar este hijo 'absolute' -->
    <p>Contenido del modal</p>
  </div>
</div>
<div style="height: 1000px; background: rgba(31, 41, 55, 0.3);"><!-- Contenido de relleno --></div>

.header-sticky {
  position: sticky;
  top: 0; /* Se pegará al borde superior cuando el scroll lo alcance */
  background: rgba(17, 24, 39, 0.7); /* bg-gray-900 con alfa */
  backdrop-filter: blur(10px); /* Efecto Glassmorphism */
  color: white;
  padding: 1rem;
  z-index: 10; /* Asegura que esté sobre otro contenido */
  border-bottom: 1px solid rgba(55, 65, 81, 0.5);
}

.modal-backdrop {
  position: fixed; /* Ocupa toda la pantalla, no se mueve con scroll */
  top: 0; left: 0; right: 0; bottom: 0;
  background: rgba(0, 0, 0, 0.8);
  backdrop-filter: blur(5px);
  z-index: 100; /* Sobre todo */
  display: flex;
  align-items: center;
  justify-content: center;
}

.modal-content {
  position: relative; /* Contexto para el botón de cerrar */
  background: #1f2937; /* bg-gray-800 */
  color: white;
  width: 90%;
  max-width: 500px;
  padding: 20px;
  border-radius: 8px;
  border: 1px solid #374151; /* bg-gray-700 */
  box-shadow: 0 10px 30px rgba(0,0,0,0.5);
}

.modal-close-btn {
  position: absolute;
  top: 10px;
  right: 10px;
  background: none;
  border: none;
  font-size: 1.5rem;
  color: #9ca3af; /* bg-gray-400 */
  cursor: pointer;
  transition: color 0.3s ease;
}
.modal-close-btn:hover {
    color: white;
}

3.2 CSS Flexbox (Modelo 1D)

Autores/Proponentes: La especificación es del W3C, con Tab Atkins Jr. como uno de los editores principales.

Concepto (Teoría): Es un modelo de layout unidimensional (1D). Organiza elementos en una Fila (row) o en una Columna (column), pero no en ambas a la vez. Es ideal para componentes (navbars, listas de tarjetas, botones alineados).

Terminología:

  • Contenedor Flex: El elemento padre (con display: flex).
  • Items Flex: Los hijos directos del contenedor.
  • Eje Principal (Main Axis): La dirección del flex-direction (por defecto row).
  • Eje Transversal (Cross Axis): El eje perpendicular al principal.

Propiedades Clave del Contenedor:

  • display: flex
  • flex-direction: row (default), column, row-reverse, column-reverse.
  • justify-content: Alineación en el Eje Principal (flex-start, flex-end, center, space-between, space-around).
  • align-items: Alineación en el Eje Transversal (stretch, flex-start, flex-end, center).
  • flex-wrap: nowrap (default) o wrap (permite que los items salten a la siguiente línea).

Ejemplo Práctico (Navbar y Centrado):

<!-- Ejemplo 1: Navbar -->
<nav class="navbar">
  <div class="logo">MiLogo</div>
  <ul class="nav-links">
    <li><a href="#">Inicio</a></li>
    <li><a href="#">Servicios</a></li>
  </ul>
  <a href="#" class="cta-button">Login</a>
</nav>

<!-- Ejemplo 2: Centrado Perfecto -->
<div class="centering-container">
  <div class="centered-item">Estoy perfectamente centrado</div>
</div>
.navbar {
  display: flex;
  flex-direction: row; /* (Default) */
  justify-content: space-between; /* Eje Principal: separa los grupos */
  align-items: center; /* Eje Transversal: centra verticalmente */
  padding: 1rem;
  background: #1f2937; /* bg-gray-800 */
  border: 1px solid #374151; /* bg-gray-700 */
  border-radius: 8px;
  color: white;
}
.nav-links {
  display: flex;
  list-style: none;
  padding: 0; margin: 0;
}
.nav-links li {
  margin-left: 1rem;
}
.nav-links a, .cta-button {
  color: white;
  text-decoration: none;
}
.logo {
  font-weight: bold;
  color: #a3e635; /* lime-400 */
}
.cta-button {
    background: #a3e635; /* lime-400 */
    color: #1f2937; /* bg-gray-800 */
    font-weight: 600;
    padding: 0.5rem 1rem;
    border-radius: 5px;
}

.centering-container {
  display: flex;
  height: 300px; /* Necesita altura para centrar verticalmente */
  border: 1px solid #a3e635; /* border-lime-400 */
  background: #111827; /* bg-gray-900 */
  border-radius: 8px;

  /* Centrado en Eje Principal (horizontal) */
  justify-content: center;
  /* Centrado en Eje Transversal (vertical) */
  align-items: center;
}
.centered-item {
    background: #1f2937; /* bg-gray-800 */
    padding: 1rem;
    border-radius: 5px;
    border: 1px solid #374151;
}

Propiedades Clave de los Items:

  • flex-grow: (Número, default 0). Factor de "crecimiento". Si hay espacio extra, ¿cuánto de ese espacio toma este item?
  • flex-shrink: (Número, default 1). Factor de "encogimiento". Si no hay espacio, ¿cuánto se encoge este item?
  • flex-basis: (Unidad, default auto). El tamaño "ideal" o base del item antes de crecer o encogerse.
  • flex: Atajo para flex-grow flex-shrink flex-basis. (Ej. flex: 1 1 auto;).
  • align-self: Sobrescribe el align-items del contenedor solo para este item.

Ejemplo Práctico (Layout de 2 columnas):

<div class="container-items">
  <main class="content">Contenido principal...</main>
  <aside class="sidebar">Sidebar</aside>
</div>
.container-items {
  display: flex;
  border: 1px solid #374151;
  border-radius: 8px;
  overflow: hidden; /* Para que el borde redondeado afecte a los hijos */
}
.content {
  /* Crece para tomar el espacio disponible (2),
  se encoge (1),
  base de 0 (empezará desde 0 y crecerá) */
  flex: 2 1 0%;
  background: #1f2937; /* bg-gray-800 */
  padding: 1rem;
}
.sidebar {
  /* Crece (1) -> Tomará la mitad de espacio que .content */
  flex: 1 1 0%;
  background: #374151; /* bg-gray-700 */
  padding: 1rem;
  border-left: 1px solid #4b5563; /* bg-gray-600 */
}

3.3 CSS Grid (Modelo 2D)

Autores/Proponentes: Rachel Andrew y Jen Simmons son las principales educadoras y proponentes de Grid, trabajando de cerca con el W3C.

Concepto (Teoría): Es un modelo de layout bidimensional (2D). Controla Filas y Columnas simultáneamente. Es ideal para la maquetación general de la página (layouts).

Terminología:

  • Contenedor Grid: El elemento con display: grid.
  • Tracks: Las filas (rows) y columnas (columns).
  • Líneas de Grilla: Las líneas (horizontales y verticales) que separan los tracks.
  • Unidad fr: (Fraccional). Una unidad que representa una fracción del espacio disponible.

Propiedades Clave (Definición de Grilla):

  • display: grid
  • grid-template-columns: Define las columnas. (Ej. 1fr 1fr 200px -> 2 columnas fraccionales y una fija de 200px).
  • grid-template-rows: Define las filas. (Ej. auto 1fr auto -> fila 1 y 3 se adaptan al contenido, fila 2 toma el espacio restante).
  • gap (o grid-gap): El espacio (gutter) entre las celdas.

Propiedades Clave (Posicionamiento de Items):

  • grid-column-start / grid-column-end: Dónde empieza y termina el item (por número de línea).
  • grid-row-start / grid-row-end:
  • Atajo: grid-column: 1 / 3 (Empieza en línea 1, termina en línea 3, ocupando 2 columnas). grid-column: span 2 (Ocupa 2 columnas).

Ejemplo Práctico (Layout de Aplicación con grid-template-areas):

grid-template-areas: La forma más "visual" e ingenieril de definir un layout.

<div class="app-layout">
  <header class="app-header">Header</header>
  <nav class="app-sidebar">Sidebar</nav>
  <main class="app-content">Content</main>
  <footer class="app-footer">Footer</footer>
</div>
.app-layout {
  display: grid;
  height: 100vh; /* Ocupa toda la altura de la pantalla */
  
  /* Definimos las filas: 60px fija, 1fr (flexible), 100px fija */
  grid-template-rows: 60px 1fr 100px;
  
  /*
  Definimos las columnas Y las "áreas" con nombres.
  Col 1: 250px (sidebar)
  Col 2: 1fr (contenido principal)
  */
  grid-template-columns: 250px 1fr;

  /*
  Definimos la plantilla visualmente:
  - Fila 1 ("header"): Ocupa ambas columnas (header header)
  - Fila 2 ("main"):   Col 1 es 'sidebar', Col 2 es 'content'
  - Fila 3 ("footer"): Ocupa ambas columnas (footer footer)
  */
  grid-template-areas:
    "header  header"
    "sidebar content"
    "footer  footer";
  gap: 5px;
  border: 1px solid #374151;
  border-radius: 8px;
  overflow: hidden;
}

/* Ahora, asignamos cada elemento a su área nombrada */
.app-header {
  grid-area: header;
  background: #374151; /* bg-gray-700 */
}
.app-sidebar {
  grid-area: sidebar;
  background: #4b5563; /* bg-gray-600 */
}
.app-content {
  grid-area: content;
  background: #1f2937; /* bg-gray-800 */
}
.app-footer {
  grid-area: footer;
  background: #374151; /* bg-gray-700 */
}

/* Estilos comunes para centrar texto */
.app-layout > * {
    display: flex;
    align-items: center;
    justify-content: center;
    font-size: 1.2rem;
    color: white;
}

Módulo 4: Diseño Responsivo (Responsive Web Design - RWD)

Asegurar que la aplicación funcione en cualquier tamaño de pantalla.

4.1 El Viewport Metatag

Concepto (Teoría): El viewport es el área visible del navegador. En móviles, los navegadores "mienten" por defecto: simulan un viewport de escritorio (ej. 980px) y luego "alejan" la página para que quepa. Esto hace el texto ilegible.

El Metatag: Esta etiqueta le dice al navegador: "No mientas. Configura el ancho del viewport para que sea igual al ancho del dispositivo (width=device-width) y empieza sin zoom (initial-scale=1.0)".

Ejemplo Práctico (Requerido en el <head> de toda página responsiva):

<head>
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
</head>

4.2 Media Queries

Autor (Teoría): Ethan Marcotte acuñó el término "Responsive Web Design" en un artículo de A List Apart en 2010. RWD se basa en 3 pilares:

  1. Una grilla fluida (Flexbox/Grid).
  2. Imágenes fluidas.
  3. Media Queries.

Concepto: Son filtros condicionales. Permiten aplicar bloques de CSS solo si se cumplen ciertas condiciones del dispositivo (ancho, alto, orientación, resolución).

Ejemplo Práctico:

/* Estilos base (para todos) */
.container {
  width: 90%;
  margin: 0 auto;
}

/*
Media Query:
Si el ancho del viewport es 600px O MÁS...
*/
@media (min-width: 600px) {
  .container {
    width: 80%; /* ...hacemos el contenedor más ancho */
  }
}

/*
Si el ancho del viewport es 1200px O MÁS...
*/
@media (min-width: 1200px) {
  .container {
    max-width: 1140px; /* ...le damos un ancho fijo máximo */
  }
}

/* Media query para impresión */
@media print {
  body {
    font-family: 'Times New Roman', serif;
    color: black;
    background: white;
  }
  .navbar, .app-footer, .header-sticky {
    display: none; /* Oculta navbar y footer al imprimir */
  }
}

4.3 Estrategia "Mobile First"

Autor (Teoría): Luke Wroblewski es el principal proponente de esta estrategia.

Concepto: En lugar de diseñar para escritorio y luego "quitar" cosas para móvil (Desktop-First, usando max-width), diseñamos para la restricción (Móvil) primero, y luego "añadimos" complejidad a medida que la pantalla crece (Mobile-First, usando min-width).

Ventajas:

  • CSS más limpio y menos sobrescrituras.
  • Mejor rendimiento en móviles (cargan un CSS más simple).
  • Fuerza a priorizar el contenido esencial.

Ejemplo Práctico (Layout de Tarjetas):

<div class="card-container">
  <div class="card">Tarjeta 1</div>
  <div class="card">Tarjeta 2</div>
  <div class="card">Tarjeta 3</div>
</div>
/* 1. Estilos Mobile-First (por defecto) */
.card-container {
  /* En móvil, usamos Flexbox en columna */
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

.card {
  background: #1f2937; /* bg-gray-800 */
  border: 1px solid #374151; /* bg-gray-700 */
  padding: 1.5rem;
  border-radius: 8px;
  text-align: center;
  color: white;
}

/* 2. Mejora Progresiva para Tablets */
/* Si la pantalla es 768px o MÁS... */
@media (min-width: 768px) {
  .card-container {
    /* ...usamos Grid para 2 columnas */
    display: grid;
    grid-template-columns: 1fr 1fr;
  }
}

/* 3. Mejora Progresiva para Desktop */
/* Si la pantalla es 1024px o MÁS... */
@media (min-width: 1024px) {
  .card-container {
    /* ...cambiamos a 3 columnas */
    grid-template-columns: 1fr 1fr 1fr;
  }
}

4.4 Imágenes Responsivas

Concepto (Teoría): Servir imágenes tiene dos problemas:

  1. Layout: La imagen no debe desbordar su contenedor (la "imagen fluida").
  2. Rendimiento: No debemos enviar una imagen de 4000px a un teléfono móvil (desperdicio de datos).

Práctica (Layout): La "imagen fluida" es la solución más simple.

img {
  max-width: 100%; /* La imagen nunca será más ancha que su contenedor */
  height: auto;  /* Mantiene la proporción */
}

Práctica (Rendimiento): Usamos HTML (no CSS) para permitir que el navegador elija la mejor imagen.

  • srcset: Provee una lista de imágenes y sus anchos (w).
  • sizes: Le dice al navegador qué tan ancha será la imagen en diferentes breakpoints (para que pueda calcular cuál srcset descargar).
  • <picture>: Se usa para dirección de arte (imágenes diferentes, ej. vertical en móvil, horizontal en desktop).

Ejemplo Práctico (HTML para rendimiento):

<!-- Ejemplo con srcset y sizes -->
<img
  srcset="https://placehold.co/480x300?text=IMG+PEQ 480w,
          https://placehold.co/800x500?text=IMG+MED 800w,
          https://placehold.co/1200x750?text=IMG+GRANDE 1200w"
  sizes="(min-width: 1024px) 50vw, 100vw"
  src="https://placehold.co/800x500?text=IMG+MED" <!-- Fallback -->
  alt="Descripción de la imagen"
  style="max-width: 100%; height: auto; border-radius: 8px;">

<!-- Ejemplo para Dirección de Arte -->
<picture>
  <!-- Si la pantalla es 768px+, usa la imagen horizontal -->
  <source media="(min-width: 768px)" srcset="https://placehold.co/800x400?text=Horizontal">
  <!-- Si no, usa la imagen vertical -->
  <source media="(max-width: 767px)" srcset="https://placehold.co/400x600?text=Vertical">
  <!-- Fallback -->
  <img src="https://placehold.co/800x400?text=Horizontal" alt="..." style="max-width: 100%; height: auto; border-radius: 8px;">
</picture>

Módulo 5: Técnicas Avanzadas y Efectos Visuales

Añadir interactividad y "pulido" (polish) a la UI.

5.1 Pseudo-clases

Concepto (Teoría): Selectores que apuntan a un elemento basado en su estado o posición en el DOM, no en su nombre, clase o ID.

Tipos:

  • Estado de UI: :hover (cursor encima), :focus (seleccionado con Tab o click, crucial para accesibilidad), :active (click presionado), :disabled (campo de formulario deshabilitado).
  • Estructurales: :first-child, :last-child, :nth-child(n) (selecciona el enésimo hijo), :not(selector) (negación).

Ejemplo Práctico (Tabla "Zebra" y Foco):

<input type="text" placeholder="Tu nombre" class="input-foco">
<table class="tabla-zebra">
  <tbody>
    <tr><td>Fila 1</td></tr>
    <tr><td>Fila 2</td></tr>
    <tr><td>Fila 3</td></tr>
    <tr><td>Fila 4</td></tr>
  </tbody>
</table>
.input-foco {
    background-color: #1f2937; /* bg-gray-800 */
    border: 2px solid #374151; /* bg-gray-700 */
    padding: 0.5rem;
    border-radius: 5px;
    color: white;
    transition: all 0.3s ease;
}
/* Estilo de Foco para Accesibilidad */
.input-foco:focus {
  border-color: #a3e635; /* lime-400 */
  box-shadow: 0 0 10px rgba(163, 230, 53, 0.5);
  outline: none; /* Quitamos el feo borde por defecto */
}

.tabla-zebra {
    width: 100%;
    border-collapse: collapse;
}
.tabla-zebra td {
    padding: 0.75rem;
    border: 1px solid #374151; /* bg-gray-700 */
}

/* Tabla Zebra (Stripe table) */
.tabla-zebra tr:nth-child(even) { /* Selecciona las filas pares */
  background-color: #1f2937; /* bg-gray-800 */
}

/* Resaltado al pasar el cursor */
.tabla-zebra tr:hover {
  background-color: #4b5563; /* bg-gray-600 */
}

5.2 Pseudo-elementos

Concepto (Teoría): Selectores que estilizan una parte específica de un elemento, o que insertan contenido virtual antes o después del contenido real del elemento. Usan doble dos puntos (::) por estándar (aunque : funciona por retrocompatibilidad).

Tipos:

  • ::before y ::after: Crean un "elemento" virtual dentro del elemento seleccionado, antes o después de su content. Requieren la propiedad content.
  • ::first-letter: Estiliza la primera letra (ej. capitular).
  • ::placeholder: Estiliza el texto de un input placeholder.

Ejemplo Práctico (Tooltip y Custom Bullets):

<a href="#" class="tooltip" data-tooltip="Este es el mensaje">Pasa el cursor</a>

<ul class="custom-list">
  <li>Item 1</li>
  <li>Item 2</li>
</ul>
.tooltip {
  position: relative; /* Contexto para el ::after */
  color: #a3e635; /* lime-400 */
  border-bottom: 1px dotted #a3e635;
  text-decoration: none;
}
.tooltip:hover::after {
  /* Usamos el atributo 'data-tooltip' para el contenido */
  content: attr(data-tooltip);
  position: absolute;
  bottom: 125%; /* Arriba del elemento */
  left: 50%;
  transform: translateX(-50%); /* Centrado */
  background: #030712; /* bg-gray-950 */
  color: white;
  padding: 5px 10px;
  border-radius: 3px;
  white-space: nowrap; /* Evita que el texto se rompa */
  z-index: 20;
  border: 1px solid #374151;
  font-size: 0.9rem;
}

.custom-list {
  list-style-type: none; /* Quitamos bullets por defecto */
  padding-left: 0;
}
.custom-list li {
    position: relative;
    padding-left: 1.75rem; /* Espacio para el bullet */
}
.custom-list li::before {
  content: '⚡'; /* "Vistoso" bullet */
  position: absolute;
  left: 0;
  top: 0;
  font-size: 1rem;
}

5.3 Transiciones (Transitions)

Concepto (Teoría): Permiten definir una animación implícita y suave entre dos estados de un elemento (ej. el estado normal y el estado :hover).

Propiedades:

  • transition-property: Qué propiedad animar (ej. background-color, opacity, o all).
  • transition-duration: Cuánto debe durar (ej. 0.3s o 300ms).
  • transition-timing-function: La "curva" de la animación (ej. ease-in, ease-out, linear).
  • transition-delay: Cuánto esperar antes de empezar.
  • transition: El atajo para todas las anteriores.

Nota de Rendimiento: Siempre es mejor animar opacity y transform que propiedades que causan reflow (como width, height, margin).

Ejemplo Práctico (Botón con "fade"):

<a href="#" class="button-transition">Comprar Ahora</a>
.button-transition {
  background-color: #a3e635; /* lime-400 */
  color: #1f2937; /* bg-gray-800 */
  font-weight: 600;
  padding: 10px 15px;
  text-decoration: none;
  border-radius: 5px;
  display: inline-block; /* Para que el padding funcione bien */
  border: 2px solid #a3e635;

  /*
  Definición de la transición:
  Monitorea 'all' (o 'background-color', 'color', 'transform')
  dura 0.3 segundos,
  con una curva 'ease-in-out'
  */
  transition: all 0.3s ease-in-out;
}

.button-transition:hover, .button-transition:focus {
  background-color: transparent;
  color: #a3e635; /* Estado final */
  transform: translateY(-2px); /* Efecto "lift" */
  box-shadow: 0 5px 15px rgba(163, 230, 53, 0.3);
}

5.4 Transformaciones (Transforms)

Concepto (Teoría): Modifican el sistema de coordenadas de un elemento, permitiendo moverlo (translate), rotarlo (rotate), escalarlo (scale) o sesgarlo (skew).

Ventaja de Rendimiento: Las transformaciones (especialmente translate) no afectan el flujo del documento. Mover un elemento con transform: translateX(50px) es mucho más eficiente (acelerado por GPU) que moverlo con margin-left: 50px (que recalcula todo el layout).

Ejemplo Práctico (Zoom en Tarjeta):

<div class="card-zoom">
  <img src="https://placehold.co/400x300/4b5563/eee?text=Hover+Me" alt="Demo">
</div>
.card-zoom {
  overflow: hidden; /* Oculta lo que se salga de la tarjeta */
  border-radius: 8px;
  display: inline-block;
  box-shadow: 0 10px 20px rgba(0,0,0,0.4);
}
.card-zoom img {
  display: block; /* Elimina espacio fantasma bajo la imagen */
  transition: transform 0.4s ease; /* Transición para la transformación */
}

.card-zoom:hover img {
  /* Al hacer hover, escala la imagen 1.1 veces */
  transform: scale(1.1) rotate(-2deg); /* Más vistoso */
}

5.5 Animaciones (Animations)

Concepto (Teoría): Permiten animaciones explícitas y complejas, con múltiples pasos (fotogramas clave).

Teoría: Se definen en dos partes:

  1. @keyframes: La regla que define los pasos de la animación (usando from/to o porcentajes 0%, 50%, 100%).
  2. animation: La propiedad que aplica los keyframes a un elemento, definiendo duración, repetición (iteration-count), dirección (direction), etc.

Ejemplo Práctico (Spinner de Carga):

<div class="spinner"></div>
/* 1. Definir los keyframes de la animación "spin" */
@keyframes spin {
  /* Desde (0%) */
  from {
    transform: rotate(0deg);
  }
  /* Hasta (100%) */
  to {
    transform: rotate(360deg);
  }
}

/* 2. Aplicar la animación al elemento */
.spinner {
  width: 50px;
  height: 50px;
  border: 5px solid #374151; /* Gris claro (bg-gray-700) */
  border-top: 5px solid #a3e635; /* Verde (lime-400) */
  border-radius: 50%; /* Círculo */

  /* Aplicación */
  animation-name: spin;
  animation-duration: 1s;
  animation-timing-function: linear;
  animation-iteration-count: infinite; /* Repetir infinitamente */
}

Módulo 6: Arquitectura y CSS Escalable (El Enfoque de Ingeniería)

Cómo escribir CSS para sistemas grandes y mantenibles.

6.1 Variables CSS (Custom Properties)

Concepto (Teoría): Variables nativas de CSS. Son dinámicas (pueden cambiar en runtime) y respetan la cascada y la herencia (tienen scope). Son la base del theming moderno (ej. Modo Oscuro).

Sintaxis:

  • Definición: --nombre-variable: valor; (usualmente en el selector :root para que sean globales).
  • Uso: color: var(--nombre-variable);

Ejemplo Práctico (Theming Modo Oscuro):

(Este ejemplo requeriría JS para añadir/quitar la clase .dark-mode al <body>. Aquí solo mostramos el CSS.)

/* 1. Definición de variables globales (Tema Claro por defecto) */
:root {
  --color-fondo: #FFFFFF;
  --color-texto: #333333;
  --color-primario: #a3e635; /* lime-400 */
}

/* 2. Redefinición de variables para el Tema Oscuro */
body.dark-mode {
  --color-fondo: #111827; /* bg-gray-900 */
  --color-texto: #d1d5db; /* bg-gray-300 */
  --color-primario: #bef264; /* lime-300 */
}

/* 3. Uso de las variables */
body {
  background-color: var(--color-fondo);
  color: var(--color-texto);
  transition: background-color 0.3s, color 0.3s;
}

.button {
  background-color: var(--color-primario);
  --color-btn-texto: #111827; /* Texto oscuro para botón claro */
  color: var(--color-btn-texto);
}

/* Si está en dark-mode, el botón puede necesitar texto claro */
body.dark-mode .button {
    --color-btn-texto: #111827;
}

(Nota: Esta página ya usa un tema oscuro por defecto, pero el principio de variables es el mismo).

6.2 Metodologías de Nomenclatura: BEM

Autor (Teoría): Desarrollado por el equipo de Yandex.

Concepto: BEM (Block, Element, Modifier) no es un framework, es una convención de nomenclatura estricta para las clases de CSS.

Objetivo: Evitar colisiones de nombres y problemas de especificidad en proyectos grandes. Produce CSS "plano" (sin anidamiento) y modular.

Reglas:

  • Block: El componente padre, auto-contenido (ej. .card, .menu).
  • Element: Una parte dentro del bloque (ej. .card__title, .menu__item). Se denota con doble guion bajo (__). Un elemento no puede vivir fuera de su bloque.
  • Modifier: Una variación de un bloque o un elemento (ej. .card--featured, .menu__item--active). Se denota con doble guion (--).

Ejemplo Práctico (Componente Card):

<!-- BLOQUE: .card -->
<article class="card-bem">
  <!-- ELEMENTO: .card-bem__image -->
  <img class="card-bem__image" src="https://placehold.co/400x200" alt="">
  <!-- ELEMENTO: .card-bem__content -->
  <div class="card-bem__content">
    <!-- ELEMENTO: .card-bem__title -->
    <h3 class="card-bem__title">Título del Card</h3>
  </div>
</article>

<!-- BLOQUE con MODIFICADOR: .card-bem--featured -->
<article class="card-bem card-bem--featured">
  <img class="card-bem__image" src="https://placehold.co/400x200" alt="">
  <div class="card-bem__content">
    <h3 class="card-bem__title">Card Destacado</h3>
  </div>
</article>
/*
Notar que no hay anidamiento de selectores.
Cada selector tiene la especificidad baja de una sola clase.
*/

/* BLOQUE */
.card-bem {
  border: 1px solid #374151; /* bg-gray-700 */
  border-radius: 5px;
  background: #1f2937; /* bg-gray-800 */
  margin-bottom: 1rem;
  overflow: hidden;
}

/* ELEMENTOS */
.card-bem__image {
  width: 100%;
}
.card-bem__content {
  padding: 1rem;
}
.card-bem__title {
  font-size: 1.2rem;
  margin: 0;
  color: white; /* Sobrescribir estilos base de 'prose' */
}

/* MODIFICADOR */
.card-bem--featured {
  border: 2px solid #a3e635; /* lime-400 */
  box-shadow: 0 4px 10px rgba(163, 230, 53, 0.3);
}

6.3 Preprocesadores: SASS (SCSS)

Autor (Teoría): Hampton Catlin creó SASS (Syntactically Awesome StyleSheets).

Concepto: Un preprocesador es un lenguaje de scripting que compila a CSS. No se ejecuta en el navegador. Añade características de lenguaje de programación a CSS (variables, anidamiento, funciones, mixins).

Sintaxis: Usaremos SCSS, que es un super-set de CSS (todo CSS válido es SCSS válido).

Ejemplo Práctico (SCSS):

/* styles.scss (Este archivo se compila a styles.css) */

/* 1. Variables ($) */
$primary-color: #a3e635; /* lime-400 */
$dark-text: #111827;
$font-stack: 'Roboto', sans-serif;

/* 2. Anidamiento (Nesting) */
.navbar-scss {
  background-color: $primary-color;
  padding: 1rem;

  ul { /* Se compila a: .navbar-scss ul */
    display: flex;
    list-style: none;
  }

  li { /* Se compila a: .navbar-scss li */
    margin-left: 1rem;
  }

  a { /* Se compila a: .navbar-scss a */
    color: $dark-text;
    text-decoration: none;

    /* Referencia al padre (&) */
    &:hover { /* Se compila a: .navbar-scss a:hover */
      text-decoration: underline;
    }
  }
}

/* 3. Mixins (Bloques de código reusables) */
@mixin border-radius($radius) {
  -webkit-border-radius: $radius;
  -moz-border-radius: $radius;
  border-radius: $radius;
}

.button-scss {
  background: $primary-color;
  color: $dark-text;
  font-weight: 600;
  @include border-radius(5px); /* Usamos el mixin */
  padding: 0.5rem 1rem;
  text-decoration: none;
}

6.4 Optimización y Rendimiento

Concepto (Teoría): El CSS es un recurso que bloquea el renderizado (Render-Blocking Resource). El navegador no mostrará nada en pantalla hasta que haya descargado y parseado todo el CSS del <head>.

El Camino Crítico de Renderizado (Critical Rendering Path): Es la secuencia de pasos que el navegador sigue para pintar la página.

Estrategia:

  1. Minificar y Concatenar: Reducir el tamaño del CSS (quitando espacios en blanco) y combinar múltiples archivos .css en uno solo (para reducir peticiones HTTP). (Herramientas como Webpack o Vite hacen esto automáticamente).
  2. CSS Crítico (Critical CSS): Identificar el CSS mínimo necesario para renderizar la parte above-the-fold (lo que se ve sin hacer scroll).
  3. Implementación:
    • Poner el CSS Crítico en línea (<style>...css crítico...</style>) en el <head>.
    • Cargar el resto del CSS (el no-crítico) de forma asíncrona para que no bloquee el renderizado.

Ejemplo Práctico (Carga Asíncrona):

<head>
  <!-- 1. CSS Crítico (para el header y layout base) en línea -->
  <style>
    body { margin: 0; font-family: sans-serif; background: #111827; }
    .header { background: #1f2937; color: white; padding: 1rem; }
    /* ...otros estilos críticos... */
  </style>

  <!--
  2. Carga del CSS completo (No bloqueante)
  rel="preload" le dice al navegador que lo descargue pronto.
  as="style" le dice qué es.
  onload="..." lo aplica a la página UNA VEZ que se ha cargado.
  -->
  <link rel="preload" href="full-styles.css" as="style" onload="this.onload=null;this.rel='stylesheet'">

  <!-- Fallback para navegadores sin JS -->
  <noscript><link rel="stylesheet" href="full-styles.css"></noscript>
</head>

Módulo 7: El Ecosistema Moderno y Futuro de CSS

Cómo se integra CSS en el stack de desarrollo front-end.

7.1 Frameworks CSS: La Decisión

Concepto (Teoría): Herramientas que proveen CSS (y a veces JS) pre-escrito para acelerar el desarrollo.

Tipo 1: Frameworks Basados en Componentes (Ej. Bootstrap)

  • Autor: Creado por Twitter.
  • Filosofía: Provee componentes listos para usar (.card, .modal, .navbar).
  • Pros: Prototipado extremadamente rápido. Buena documentación.
  • Contras: Las webs terminan pareciéndose entre sí. Alta especificidad, lo que dificulta la personalización (mucho override).
Ejemplo (Bootstrap):
<!-- Esto requeriría el CSS de Bootstrap para funcionar -->
<button type="button" class="btn btn-primary">
  Botón Primario de Bootstrap
</button>

Tipo 2: Frameworks Utility-First (Ej. Tailwind CSS)

  • Autor: Creado por Adam Wathan.
  • Filosofía: No provee componentes. Provee clases "atómicas" de bajo nivel (.pt-4, .flex, .text-lg, .bg-blue-500). Los componentes se construyen componiendo estas utilidades en el HTML.
  • Pros: Altamente personalizable. Sin colisiones de nombres. El CSS final es muy pequeño (usando purging). Muy popular en el desarrollo de aplicaciones modernas.
  • Contras: El HTML se vuelve "sucio" (lleno de clases). Requiere un build step (compilación). (Esta página usa Tailwind).
Ejemplo (Tailwind CSS):
<!-- Este botón usa las clases de Tailwind cargadas en esta página -->
<button class="
  bg-lime-500      
  hover:bg-lime-600 
  text-gray-900    /* Texto oscuro para contraste */
  font-bold        
  py-2             
  px-4             
  rounded          
  transition-all
  duration-300
  transform
  hover:scale-105
">
  Botón de Tailwind
</button>

7.2 CSS-in-JS

Concepto (Teoría): Una técnica, popularizada por el ecosistema React, donde el CSS se escribe directamente en los archivos JavaScript del componente.

  • Autor/Ejemplo: Styled Components (creado por Max Stoiber y Glen Maddern).
  • Filosofía: Elimina la brecha entre JS y CSS. El CSS tiene scope automático al componente (no hay colisiones globales). Permite lógica JS (props) directamente en el CSS.
  • Pros: Mantenibilidad a escala de componente. Sin clases globales.
  • Contras: Requiere JS para funcionar (problemas de FOUC - Flash of Unstyled Content). Curva de aprendizaje.

Ejemplo Práctico (React con Styled Components):

// Button.js (Un componente de React)
import React from 'react';
import styled from 'styled-components'; // Importa la librería

// Crea un componente <Button> que es un <button> HTML
// con estilos adjuntos (usando Template Literals)
const Button = styled.button`
  background: transparent;
  border-radius: 3px;
  border: 2px solid #a3e635; /* lime-400 */
  color: #a3e635;
  margin: 0.5em 1em;
  padding: 0.25em 1em;
  transition: all 0.3s ease;

  /* Podemos usar 'props' de React para lógica */
  background: ${props => props.primary ? '#a3e635' : 'transparent'};
  color: ${props => props.primary ? '#111827' : '#a3e635'};
  
  &:hover {
      background: ${props => props.primary ? '#bef264' : 'rgba(163, 230, 53, 0.1)'};
  }
`;

// Uso:
// <Button>Botón Normal</Button>
// <Button primary>Botón Primario</Button>

7.3 El Futuro: ¿Qué viene?

Concepto (Teoría): El CSS evoluciona constantemente. Las siguientes características ya son (o están siendo) implementadas en navegadores modernos.

1. Container Queries (@container)

  • Teoría: El "santo grial" del RWD. En lugar de que un componente responda al viewport (@media), responde al tamaño de su contenedor padre.
  • Caso de uso: Una tarjeta (.card) que se ve "vertical" si su contenedor es estrecho, y "horizontal" si su contenedor es ancho, independientemente del ancho de la página.
Ejemplo Práctico (@container):
.card-container {
  /* Le dice al navegador que monitoree el ancho de este elemento */
  container-type: inline-size;
  container-name: card-container;
}

/*
Aplica estos estilos al .card
SI su contenedor llamado 'card-container'
tiene al menos 400px de ancho.
*/
@container card-container (min-width: 400px) {
  .card {
    display: flex; /* Cambia a layout horizontal */
  }
}

2. Selector :has()

  • Teoría: El tan esperado "selector de padre" (parent selector). Permite estilizar un elemento basado en los hijos que contiene.
  • Caso de uso: Cambiar el fondo de un <div> si contiene una imagen.
Ejemplo Práctico (:has()):
/* Selecciona cualquier 'figure' QUE CONTENGA un 'figcaption' */
figure:has(figcaption) {
  border: 1px solid #374151;
  padding: 10px;
  background: rgba(17, 24, 39, 0.5);
}

/* Selecciona un .card QUE CONTENGA un .badge-nuevo
   y le pone un borde destacado */
.card:has(.badge-nuevo) {
  border-left: 5px solid #a3e635; /* lime-400 */
}

/* Selecciona un 'label' cuyo 'input' siguiente esté :checked */
label:has(+ input:checked) {
  font-weight: bold;
  color: #a3e635; /* lime-400 */
}

3. Nuevos Espacios de Color (ej. LCH)

  • Teoría: rgb() es limitado y no es "perceptualmente uniforme" (cambiar el valor de "azul" en 10 tiene un impacto visual diferente si es oscuro o claro).
  • lch() (Lightness, Chroma, Hue) es un espacio de color moderno que se alinea con la percepción humana, permitiendo colores más vibrantes y transiciones de color más suaves y predecibles.
