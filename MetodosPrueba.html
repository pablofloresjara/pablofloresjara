Testing Básico

El testing no es una fase aislada al final del desarrollo; es un proceso continuo de evaluación. Según Pressman, el objetivo principal es descubrir errores, no demostrar que el software funciona.

Estrategias de Diseño

Los dos enfoques principales para diseñar casos de prueba.

Funcional

Caja Negra (Black Box)

Se centra en los requisitos funcionales del software. El tester no necesita conocer la lógica interna del código. Se basa en entradas y salidas esperadas.

  • Partición de Equivalencia: Dividir entradas en clases válidas e inválidas.
  • Análisis de Valores Límite: Probar los bordes (ej: si el rango es 1-10, probar 0, 1, 10, 11).
  • Grafos Causa-Efecto: Relacionar efectos lógicos.

Estructural

Caja Blanca (White Box)

Se basa en un examen minucioso de los detalles procedimentales. Se prueban los caminos lógicos (bucles, condiciones) del código fuente.

  • Prueba del Camino Básico: Asegurar que cada línea se ejecute al menos una vez.
  • Complejidad Ciclomática: Métrica de McCabe V(G) = E - N + 2.
  • Prueba de Condición: Ejercitar las variables lógicas (True/False).
public void test(int x) { if (x > 0) { // Nodo 1 print("Pos"); // Nodo 2 } else { print("Neg"); // Nodo 3 } } // Nodo 4 (Salida)

Laboratorio: Cálculo de Complejidad Ciclomática

La complejidad ciclomática V(G) define el número de caminos independientes en el conjunto básico de un programa. Una complejidad mayor a 10 suele indicar alto riesgo de defectos.

El Plan de Prueba

Estructura basada en el estándar IEEE 829

Define qué se va a probar y qué NO se va a probar. Establece los límites del proyecto de testing, incluyendo funcionalidades críticas, integraciones con terceros y requisitos de seguridad.
  • Hardware: Servidores, dispositivos móviles, PCs.
  • Software: Sistemas operativos, navegadores, herramientas de automatización (Selenium, JUnit).
  • Datos de prueba: Bases de datos de prueba, stubs, mocks.
Describe los tipos de pruebas a realizar (Unitarias, Integración, Estrés) y asigna tiempos estimados. Define los criterios de inicio (entry criteria) y finalización (exit criteria) de las pruebas.
Documentos que se generarán:
  • Plan de Pruebas (este documento).
  • Especificación de Casos de Prueba.
  • Reportes de Incidentes (Bugs).
  • Informe Resumen de Pruebas.
