Ingeniería de Software

"La ingeniería de software trata de establecer y usar principios de ingeniería robustos para obtener software económico, fiable y que funcione en máquinas reales" (Fritz Bauer).

Conceptos Fundamentales

Según Sommerville, el software no es solo el programa ejecutable, sino toda la documentación asociada y los datos de configuración necesarios para que el sistema funcione correctamente.

¿Por qué modelar?

"Un modelo es una simplificación de la realidad". Modelamos para comprender el sistema antes de construirlo. UML (Unified Modeling Language) es el estándar gráfico para este propósito.

Diagrama de Casos de Uso

"Muestra qué hace el sistema, no cómo lo hace".

Es una técnica de modelado para capturar los requerimientos funcionales del sistema.

Actor: Alguien o algo externo al sistema (Persona, otro Software).
Caso de Uso: Una funcionalidad específica (Ej: "Registrar Pedido").
Relación: Conexión entre un actor y un caso de uso.

Ejemplo: Sistema de Biblioteca

Diagrama de Clases

Representa la estructura estática del sistema: qué objetos existen y cómo se relacionan.

Estructura de una Clase

Coche
- marca: String
- modelo: String
- velocidad: int
+ acelerar()
+ frenar()
+ obtenerInfo()

Relaciones Fundamentales:

1. Herencia (Generalización): Una clase "Hija" hereda de una clase "Padre". Ej: Un Gato es un Animal.
2. Asociación: Relación estructural entre clases. Ej: Un Cliente realiza un Pedido.
3. Agregación: Relación "todo-parte". Ej: Una Universidad tiene Departamentos.
